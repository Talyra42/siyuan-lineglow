# Siyuan Line Glow

给思源笔记的代码块做「指定行高亮」的插件：用 VitePress 的行区间语法，把讲解重点的那几行标出来。

## 为什么要做这个

写教程或者写笔记时，经常需要说「注意第 4 到 6 行」。思源原生没有这个能力，而常见的 ` ```js {4-6} ` 这种围栏写法在思源里**行不通**：思源的 Markdown 引擎 Lute 在解析围栏信息时会在第一个空格处截断，`{4-6}` 会在解析阶段就被丢掉，既进不了渲染结果也保存不下来。

所以这个插件换了一条路：把行区间存进代码块的**块属性** `custom-code-hl`，渲染时再把高亮画出来。属性会随着 `.sy`、同步、历史一起走，也不影响代码块原本的语言识别。

## ✨ 功能

- 🎯 **指定行高亮** - 支持单行、区间与多段，写法与 VitePress 一致
- 🎨 **整行背景** - 颜色与不透明度可调，深浅主题下都好看
- 🔢 **行号联动** - 高亮所在行的行号同步变色，可选加粗
- ⚙️ **按块覆盖** - 单个代码块可用属性覆盖全局样式，不想高亮的块单独关掉
- ⌨️ **快捷键** - 默认 `⌥⌘H`，可在 `设置` - `快捷键` 中修改
- 🌐 **多语言** - 内置简体中文与英文界面

## 📦 安装

### 集市安装（推荐）

1. 打开思源笔记
2. 进入 `设置` - `集市` - `插件`
3. 搜索 `Line Glow`
4. 安装并启用

### 手动安装

1. 从 [Releases](https://github.com/Talyra42/siyuan-lineglow/releases) 下载 `package.zip`
2. 解压到工作空间的 `data/plugins/siyuan-lineglow` 目录
3. 重启思源，在 `设置` - `集市` - `已下载` 中启用

> 工作空间是包含 `data` 文件夹的那个目录，不是某本笔记的目录。

## 🚀 使用

三种入口，用哪个都行：

| 入口     | 操作                                             |
| -------- | ------------------------------------------------ |
| 块标菜单 | 点击代码块左侧块标 → `插件` - `Line Glow 行高亮` |
| 快捷键   | 光标放在代码块内，按 `⌥⌘H`                       |
| 块属性   | 在块属性面板里直接编辑 `custom-code-hl`          |

对话框里输入行区间，**输入过程中右侧会实时预览**，确认后写入属性。

## 📝 行区间语法

与 VitePress 完全一致，行号从 1 开始，区间为闭区间：

| 取值      | 含义                    |
| --------- | ----------------------- |
| `3`       | 只高亮第 3 行           |
| `4-6`     | 高亮第 4 到第 6 行      |
| `1,4-6,9` | 高亮第 1、4、5、6、9 行 |

几个小技巧：

- 想高亮整块代码，填 `1-9999` 就行，超出行数的部分会被自动忽略
- 多段之间用**英文逗号**分隔，用中文逗号会被当成无效片段跳过
- 区间会自动合并去重，`1,2,3` 与 `1-3` 等价

## 🎛️ 样式

全局样式在 `设置` - `集市` - `已下载` - `Line Glow` 的齿轮里配置：总开关、背景开关/颜色/不透明度、行号开关/颜色/加粗。

想给**某个代码块**单独调样式，在它的块属性里加 `custom-code-hl-style`（与 `custom-code-hl` 一样写在块属性面板）：

| 标记             | 作用                |
| ---------------- | ------------------- |
| `bg` / `no-bg`   | 开启 / 关闭整行背景 |
| `num` / `no-num` | 开启 / 关闭行号变色 |
| `all` / `none`   | 全部开启 / 全部关闭 |

例如某个代码块只想让行号变色、不要背景，就写 `custom-code-hl-style="num,no-bg"`。没有写这个属性的块一律沿用全局设置。

## ❓ 常见问题

**为什么不能写成 ` ```js {4-6} `？**
因为思源的解析器会截断围栏信息（详见上面的「为什么要做这个」）。围栏语法在这里不是"还没支持"，而是"存不下来"。

**哪些导出会保留高亮？**
导出为图片、复制为 PNG 会保留：这两个入口在运行中的思源里渲染整篇文档，插件能像平时一样给代码块上色。导出 PDF 与导出 HTML 会生成一个独立页面，那个页面不加载插件代码，因此没有高亮。这是已知限制，代码块本身与属性都不受影响，在思源里看、同步、导出后回来编辑都正常。

**为什么行号没有变色？**
行号变色只在代码块开启了行号显示时可见。如果那个代码块没开行号（块菜单里的 `行号`），就只会看到整行背景。

**卸载插件后笔记会坏吗？**
不会。插件只往代码块加了一个 `custom-*` 属性，卸载后属性仍在但不再渲染，笔记、搜索、导出全都正常。

## ⚡ 性能与稳定性

- **不改动代码块结构**：高亮完全由代码正文元素的内联样式与一条注入的 CSS 规则实现，不往块里插任何节点，因此不会被思源序列化写进笔记，也不影响光标与撤销
- **图层数量恒定**：所有行带合并进同一条竖向渐变，不管高亮多少段，永远只有 1 个背景图层
- **有防抖也有上限**：DOM 变化以 160ms 防抖合并；单块最多处理 200 段区间，属性超过 4096 字符直接忽略
- **首帧就绪**：打开或重新打开文档时，高亮与代码块在同一帧出现，不会先显示无高亮的代码再弹出
- **长文档分批**：整篇扫描按每批 40 个代码块让出主线程
- **无泄漏**：卸载时移除全部监听、观察器与注入样式，ResizeObserver 观察过的失效节点会在全量扫描时释放

## 🛠️ 开发

需要 [NodeJS](https://nodejs.org/en/download) 与 [pnpm](https://pnpm.io/installation)。

| 命令             | 作用                                                                           |
| ---------------- | ------------------------------------------------------------------------------ |
| `pnpm install`   | 安装依赖                                                                       |
| `pnpm dev`       | 监听构建到 `<工作空间>/data/plugins/siyuan-lineglow`                           |
| `pnpm test`      | 单元测试、DOM 集成测试、扫描器生命周期测试与性能护栏                           |
| `pnpm typecheck` | 类型检查                                                                       |
| `pnpm lint`      | 代码检查                                                                       |
| `pnpm format`    | 用 Prettier 格式化仓库（`pnpm format:check` 只校验不写回）                     |
| `pnpm build`     | 生成 `dist/` 与发布用的 `package.zip`                                          |
| `pnpm release`   | 交互式发版：改版本号与 CHANGELOG → 提交 → 打标签 → 推送（CI 会自动建 Release） |

版本历史见 [CHANGELOG.md](./CHANGELOG.md)。

### 改完代码怎么在思源里看到

`pnpm dev` 只负责把改动编译进工作空间，**不会自动刷新思源界面**。改完代码后：

1. 保持 `pnpm dev` 在终端里运行，等它提示构建完成
2. 在思源里执行 `设置` - `应用` - `维护` - `刷新界面`
3. 如果只改了文案之类的少量内容，也可以在 `设置` - `集市` - `已下载` 里把插件关掉再打开

> 之所以没有自动热重载：思源桌面端的页面里没有 livereload 客户端脚本，装了也刷不动；而模板自带的 livereload 插件会在 `data/plugins` 目录上建立文件监视，这个目录同时被思源占用，在 Windows 上会抛 `EBUSY: resource busy or locked` 并直接中断构建。所以这里没有启用它，只在项目自己的源文件上做监听。

`asset/` 里是图标与预览图的 SVG 源文件；修改后重新导出为根目录的 `icon.png`（160×160）与 `preview.png`（1024×768）即可。
